# Client Review v3 — Refined Spec

Raw notes (Spanish, shorthand) refined into actionable items through a
grilling session on 2026-11-13. Each item carries the original note, the
resolved decision (including clarifications given during grilling), and
concrete work pointers. Two items are explicitly open/deferred — see the
bottom section. **Nothing in this file has been implemented yet** — this is
the refined spec only, per the request to start there.

## General (mobile, site-wide)

### 1. Inconsistent spacing between sections and titles
> Original: "Revisar los espacios... Hay espacios entre secciones y entre
> titulos que es demasiado amplio. Quiero que revises la consistencia de
> estos espacios en mobile."

**Decision:** A dedicated mobile spacing-consistency sweep, scoped to two
specific things — **inter-section vertical spacing** (the margin/padding
between one block and the next) and **title spacing** (the gap between a
section's heading and the content below it) — not a general re-audit of
everything. Needs a block-by-block pass comparing each section's mobile
`my-*`/`py-*` values against its neighbors, since this codebase has many
components each hand-tuning their own spacing (`my-29.75`, `my-20`, `my-16`,
`my-4`, etc. — no shared spacing scale/token exists). Decide on a small
consistent scale for mobile (e.g. one value for "between sections", one for
"title to content") and bring every block in line with it.

**Work:** Build a list of every block's current mobile spacing values (not
enumerated here — needs a live pass with real content), then normalize.

### 2. Fixed navigation bar
> Original: "Fixed barra de navegación"

**Decision:** `components/common/Navbar.tsx`'s `<header>` currently scrolls
away with the page (no `fixed`/`sticky` positioning at all). Make it
**`sticky` at the top** (`position: sticky; top: 0`) rather than `fixed` —
sticky doesn't require manually offsetting every page's content by the
navbar's height the way `fixed` would, and behaves identically from the
user's perspective (stays visible while scrolling).

**Work:**
- `components/common/Navbar.tsx` line 18: `<header className="border-b
  border-border bg-navbar">` → add `sticky top-0 z-40` (z-index below the
  mobile menu panel's `z-50` and the Focus Areas Detail modal's `z-[200]`,
  so neither gets covered by the sticky header).

### 3. Mobile menu: flag on the right
> Original: "Cuando el menú está abierto: Bandera a la derecha"

**Decision:** `components/common/MobileNav.tsx` lines 44–47 — the open
panel's bottom row currently renders flag-then-language-switcher,
left-aligned together. Move the flag to the **right edge of that row**
(language switcher on the left, flag on the right).

**Work:** `components/common/MobileNav.tsx`: change the row to
`justify-between` (or reorder the two children), keeping both elements as
they currently look.

### 4. Five Focus Areas: center the last (unpaired) card
> Original: "Mobile: Focus area el último poner en el centro"

### 11. News: duplicate content + layout with fewer items
> Original: "Cambiar las news para que agarren el cms... Pareciera que hay
> solo dos noticias cargadas en el cms, pero aparece la misma noticia
> repetida varias veces... ademas chequear que la interfaz se vea
> correctamente tanto para desktop como para mobile cuando hay menos."

**Decision:** The News block *already* reads from Sanity (confirmed — each
item references a `news` document, title/date/image/category/URL all
CMS-editable). The actual problem, confirmed live: the Results page's
"Communication" `newsList` block references the **same News document six
times** (there are only 2 real News documents in the whole dataset; the
other one is never referenced anywhere). This is a CMS curation mistake —
someone added the same reference repeatedly instead of picking distinct
items.

Separately, a real layout gap: the grid is a fixed `lg:grid-cols-3`
regardless of how many items exist, so with only 1–2 News items the grid
still reserves a 3rd empty column, leaving a visible gap in the bordered
box.

**Work:**
- **Content fix (Studio, not code):** the editor needs to remove the 5
  duplicate references on the "Communication" block and add the second real
  News document (and/or more) instead.
- **Code safeguard:** `components/blocks/NewsList.tsx` — dedupe
  `block.news` by `_id` before mapping, so an accidental duplicate
  reference can't visually repeat the same card again even if it happens
  again.
- **Layout fix:** `components/common/NewsList.tsx` — the grid's column
  count should cap at the actual item count (`Math.min(news.length, 3)`)
  instead of always reserving 3, so 1–2 items render in a tighter box with
  no empty gap. Verify both desktop and mobile with 1 and 2 items once
  live.

## Collaborate

### 15. Mobile: graph box overflows and gets covered by the panel
> Original: "What's already happening, la caja tapa el gráfico"

**Decision:** Root cause: in the v1_it1 pass, the mobile un-hide of this
graph (`components/common/FocusAreasBreakdown.tsx` line 168) added a fixed
`h-80` wrapper around the heading + graph **without `overflow-hidden`** —
if the SVG renders taller than the 320px box (likely, since it shares that
height with the `<h3>` heading above it), the excess spills downward,
unclipped, into the `FocusAreaBreakdownPanel` stacked right below it on
mobile. This is a regression from that earlier change, not a new ask.

**Work:** `components/common/FocusAreasBreakdown.tsx` line 168: `<div
className="h-80 lg:h-auto">` → add `overflow-hidden`.

### 16. Mobile: graph should visibly move when the user scrolls to it
> Original: "Cuando el usuario llega se mueve un poco para indicar
> movimiento"

**Decision:** `InitiativesGraph` already has a one-time entrance
rotation on mount (`ROTATION_ENTRANCE_OFFSET`, from the original v1 pass).
On mobile, this Collaborate-page instance sits far enough down the page that
the animation has already finished playing by the time a visitor scrolls to
it — so it reads as static. Best-guess fix (flagging this as inferred,
not explicitly confirmed): trigger that entrance animation on
**scroll-into-view** instead of on mount, at least for this instance.

**Work:** `components/common/InitiativesGraph.tsx`: gate the entrance
rotation's start on an `IntersectionObserver` triggering once the graph
enters the viewport, rather than unconditionally on mount. Verify this
doesn't change the already-correct desktop/Initiatives-page behavior, where
the graph is usually in view immediately.

### 17. "Looking for partners" → empty/outline dot on the Collaborate graph too
> Original: "Grafico: circulo vacío cuando es looking for partners"

**Decision:** The v1_it1 pass added this fill/outline treatment to the
**Initiatives page's** graph only, explicitly scoping out this Collaborate
instance (`FocusAreasBreakdown.tsx`) because its flattened initiative list
didn't carry `status` through. Now explicitly requested here too — extend
it. The underlying data is already fetched (`FocusAreaBreakdownInitiative`

**Work:** `components/common/FocusAreasBreakdown.tsx`'s `flatInitiatives`

### 18. New "Actors Graph" section
> Original: "Agregar gráfico actores" — clarified via attached reference
> image: a new two-column block ("Locally led, globally connected" in the
> reference), left side a radial graph of Actors around a dashed ring with a
> center hub icon, right side a title + body paragraph. Confirmed during
> grilling: **base this on existing sections**, and **every field must be
> CMS-editable**.

**Decision:** This is a genuinely new block, but almost everything it needs
already exists:
- `actors` documents already have `name`, `image`, and a `type` reference
  to `actorType`.
- `actorType` documents already have a translatable `label`, a stable
  `slug`, and a `color` (`colorToken` reference) — this is exactly the
  legend in the reference image (Government / Civil Society / International
  Organizations, each its own color).
- The reference image's shapes (pentagon / diamond / circle) map 1:1 to
  actor type — this needs a small shape-per-type lookup in the new
  component (keyed on the `actorType`'s `slug`, with a fallback shape for
  any type not explicitly mapped), not a new schema field — adding a
  "shape" field to the shared `actorType` document would leak a
  single-block concern into a type also used by the Footer.
- The radial positioning math (evenly spaced around a ring, curved/straight
  label placement) reuses the same `polar()`-style geometry already built
  for `InitiativesGraph.tsx`, simplified: no arcs, no connector lines, no
  interactivity/zoom — just static labeled shapes around a dashed ring with
  a center hub icon (reference image suggests the site's own logo mark,
  `/logo.svg` — flagging as an assumption to confirm once built, since the
  image doesn't make the icon's source unambiguous).

**Work:**
- **New Sanity object schema** `sanity/schemaTypes/objects/actorsGraph.ts`:
  `title` (string, required), `content` (text), `actors` (array of
  references to `actors`, curated — not auto-pulled like Territory's
  points, since this is a specific curated group for one section, not "every
  actor in the system"), `backgroundColor` (reference to `colorToken`,
  matching the right-column green background in the reference image).
  Register it into `PageData.sections` alongside the other block types
  (`sanity/schemaTypes/index.ts`, `components/blocks/index.tsx`).
- **New GROQ projection** in `lib/sanity/queries.ts`: for each referenced
  actor, project `_id, name, "image": image{...}, "type":
  type[]->{ "slug": slug.current, "label": coalesce(label[language==
  $locale][0].value, ...), "color": color->value.hex }` (first type entry
  used for the dot's color/shape if an actor has more than one — flag this
  edge case, uncommon but possible given `type` is an array).
- **New component** `components/common/ActorsGraph.tsx`: renders the
  dashed ring + center hub + legend (left column) and title/content (right
  column), closely mirroring `InitiativesGraph.tsx`'s radial math and
  `FocusAreasDetail.tsx`'s shape-cluster rendering approach, per the
  "base this on existing sections" instruction.
- **New block wrapper** `components/blocks/ActorsGraph.tsx`, following the
  same pattern as every other block wrapper in this codebase.
